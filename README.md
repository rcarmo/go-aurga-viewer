# aurga-web

A standalone Go LAN bridge with an embedded AURGA Viewer browser UI. Runtime dependencies: the binary and a browser with WebCodecs. No vendor app, cloud account, Node or Bun runtime is required.

**Experimental. Real-device HID control has not passed acceptance.** Discovery, configuration authentication, stream authentication and live H.264 video work on the tested AURGA at `192.168.1.94`, firmware `5.0.0.0`. A read-only Chromium check rendered 1920×1080 video (26 frames over three seconds), without saving screen contents. This is an initial video smoke test, not sustained-performance acceptance. Native tests, race detection and a full synthetic UDP → Go → WebSocket → browser H.264/HID roundtrip pass.

The local HTTPS service is installed at **https://192.168.1.167:9443/**. Accept its self-signed LAN certificate and enter the device passcode. It is managed by `aurga-web.service`; source is under `/workspace/projects/aurga-web`, the deployed binary and certificate state under `/workspace/deployments/aurga-web`.

## Run

Requires Go 1.25 or newer to build:

```sh
make install check
/workspace/tmp/aurga-web/build/aurga-web \
  -listen 192.168.1.167:9443 \
  -state-dir "$HOME/.config/aurga-web"
```

`make build` prints the output path. On CI or machines without writable `/workspace/tmp`, Make chooses a portable project-scoped temporary directory; `WORKSPACE_TMP_BASE` overrides its base.

Open `https://192.168.1.167:9443/`. Accept the self-signed LAN certificate warning, then enter the device passcode. A trusted TLS certificate can replace `cert.pem` and `key.pem` in the state directory. The autogenerated certificate persists across restarts.

By default the server listens only on `127.0.0.1:9443`. LAN binding requires one explicit IP. Wildcard binding and non-loopback plaintext HTTP are disabled. By default the bridge connects to the first device that responds to LAN discovery. Use `?ip=192.168.1.94` for an explicit target, or `-device` for an optional default. Query targets must be private IPv4 addresses; URLs, public IPs, loopback and IPv6 overrides are rejected. Authentication sessions are bound to the selected device.

Use a current Chrome or Edge browser first. H.264 decoding depends on browser/OS support. HEVC support varies; a codec error is shown if the browser cannot decode it. Audio streaming is experimental PCM16 playback through Web Audio. Browser autoplay rules require a tap after cookie auto-login; tapping the keyboard button also enables audio.

## Controls and credentials

- A passcode interstitial opens the video-only page. Keyboard and mouse are enabled by default after the device acknowledges input negotiation.
- Mouse buttons, wheel, direct-touch tap-to-click and touch dragging use absolute coordinates with release on pointer-up/cancel. Touch uses native Touch Events on iPad, with Pointer Events for mouse/pen. Chromium and WebKit browser→UDP tests pass; actual iPad host effects need confirmation.
- The small corner keyboard button focuses a mobile text input directly from its touch gesture. Text uses the vendor's atomic software-keyboard report (ID 10), and committed taps survive keyboard-focus transitions. Mobile typing supports ASCII and a US host keyboard layout, including Enter and Backspace; arbitrary Unicode is unsupported.
- `?view=1` explicitly opens a read-only viewer for safe diagnostics.
- Reports are paced by device acknowledgements, with bounded queues. Browser focus, negotiation and report delivery are tested end to end.
- Blur, hidden tabs and normal disconnect send release reports. Network loss can prevent release delivery; use the official app to clear stuck input if that occurs.
- Only one viewer session is admitted at a time. Control from the vendor app at the same time is not supported or tested.
- Login issues a random 256-bit, HttpOnly, Secure, SameSite=Strict cookie for 24 hours. The server maps it to the device passcode in bounded memory only. Reloads reuse authentication; restarting the server invalidates sessions. No passcodes are stored in cookies, browser storage, logs or files.
- Optional `AURGA_PASSCODE` verifies browser credentials locally before talking to the device. Otherwise the bridge checks the supplied passcode through the read-only device configuration API.
- Passcode attempts are limited to five per minute per source IP. Host and Origin checks, bounded messages, CSP and HTTPS protect the LAN-facing UI. Do not expose it to the public Internet; use a VPN for remote access.

## Checks

```sh
make check             # native tests, go vet, binary build
make race              # tests under the race detector
make browser-test      # optional: Bun, Playwright and ffmpeg development tools
make browser-e2e       # Chromium + real Go bridge + loopback UDP peer
AURGA_BROWSER=webkit make browser-e2e # WebKit native touch tap/focus; DOM drag/wheel handler tests
```

`make browser-test` serves a loopback HTTP test instance, intercepts its WebSocket with a synthetic peer, generates a blue H.264 frame, verifies real browser decoding/rendering, then tests default input, acknowledged mobile typing and synthetic PCM playback. It does not connect to the real device. Install optional browser test dependencies with `bun install`; install Chromium using Playwright if no matching browser is available. Shared workspace browsers are used automatically when present.

```sh
# Read-only real-device check. Supply AURGA_PASSCODE through a secret manager.
go run ./cmd/probe -device 192.168.1.94
# Also attempt a six-second read-only stream, without recording video:
go run ./cmd/probe -device 192.168.1.94 -stream
```

Use the same Go cache environment as the Makefile if running Go directly. `-stream-port` overrides the reconstructed stream port for verified firmware differences; it is not a port scanner.

## Protocol and limitations

The implementation reconstructs wire behaviour from the vendor's Android APK 2.3.1.45. The Go runtime does not load or redistribute the vendor's native library.

- UDP discovery: 32469.
- Read-only metadata/authentication: TCP 32465.
- Reconstructed UDP stream port: 36459.
- Protocol v3 header, passcode handshake, command acknowledgements, retry limits, video fragment reassembly and per-group acknowledgement bitmaps.
- Optional frame MD5 verification. No FEC recovery yet; missing fragments depend on retransmission.
- H.264/HEVC Annex-B buffers go over WebSocket to browser WebCodecs.
- USB HID keyboard and absolute/relative mouse report validation; browser sends absolute mouse reports.
- No firmware updates, Wi-Fi changes, reset, cloud binding, Wake-on-LAN or configuration mutation endpoints.
- Legacy TCP streaming and USB transport are not implemented.

The session handshake and video reassembly have passed an initial real-device browser check. HID wire paths have passed a full synthetic end-to-end test. A real device acknowledged an all-keys-released keyboard report; no key was pressed or mouse moved. Actual host input effects and sustained video testing still require acceptance. See [protocol notes](docs/protocol.md) and [scope](docs/scope.md).

## Disposable paths

The Makefile snapshots inherited `TMPDIR` before exporting scoped paths. Base selection is `WORKSPACE_TMP_BASE`, then in CI `RUNNER_TEMP` / inherited `TMPDIR` / `/tmp`; outside CI writable `/workspace/tmp`, then inherited `TMPDIR` / `/tmp`. Unset, empty, `0` and `false` CI flags mean local mode. Append `aurga-web` in every case.

`cache/go-build` is `GOCACHE`; `cache/go-mod` is `GOMODCACHE`; `cache/bun` is `BUN_INSTALL_CACHE_DIR`; `build` is `GOTMPDIR` and binary output; `runs` is `TMPDIR`; browser fixtures use `tests`; logs use `logs`. Installed shared browsers remain under `/workspace/bin/pw-browsers`. TLS keys/certificates are persistent service state and live outside these disposable paths.
